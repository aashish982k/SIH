NWIS — Project Design Context
Project Identity
Website Name: NWIS
Full Name: Nearby Wells Intelligence System
SIH Problem Statement: 26121
Organization / Domain: Oil India Limited — Oil & Gas / Drilling Intelligence
NWIS is an AI-powered intelligence and decision-support platform designed for drilling engineers and operational teams. It brings nearby-well information, historical drilling knowledge, geological and reservoir information, document-derived knowledge, risk indicators, and AI-assisted insights into a unified interface.
The design should communicate:
- Oil & gas industry
- Engineering precision
- Operational intelligence
- Trust and reliability
- AI-assisted decision making
- Geospatial / well intelligence
- Professional enterprise software
The visual identity should feel technical, premium, reliable, and industrial, rather than looking like a generic AI chatbot or consumer application.
Critical Design Constraint
This is an existing application.
The redesign must NOT change the existing application's functionality or information architecture.
Preserve exactly:
- Existing pages
- Existing routes
- Existing navigation structure
- Existing page purposes
- Existing forms
- Existing workflows
- Existing data
- Existing API integrations
- Existing charts and maps
- Existing authentication
- Existing AI functionality
- Existing buttons and their actions
- Existing tables and information
- Existing user interactions
The objective is:
Redesign the visual system, not redesign the application.

Do not remove existing pages simply because they do not fit the new visual style.
Do not invent a new navigation structure.
Do not replace existing functionality with mock functionality.
Do not create unnecessary new pages.
If an existing component already performs a function, keep its function and redesign its appearance.
Visual Direction
NWIS should use a dark navy + cream + blue enterprise intelligence aesthetic.
The interface should feel like a modern oil-and-gas command center combined with a premium enterprise analytics platform.
Avoid making it look:
- Like a generic dashboard template
- Like a cryptocurrency website
- Like a gaming interface
- Like a consumer AI chatbot
- Overly futuristic
- Overly neon
- Overly colorful
The interface should communicate precision and confidence rather than visual noise.
Color System
Use this palette as the primary design system.
Color	Hex	Purpose
Deep Navy	#010736	Main dark surfaces, hero areas, primary navigation
Navy	#0D1C42	Cards, panels, secondary dark surfaces
Slate Blue	#22396F	Secondary actions, active states, charts, highlights
Warm Cream	#FCF1D0	Primary accent, important highlights, alerts, key information


Color hierarchy
#010736 should be the deepest and strongest color.
#0D1C42 should create hierarchy between the main background and individual panels.
#22396F should be used for interactive and informational elements.
#FCF1D0 should be used sparingly for important emphasis.
Do not introduce random bright colors throughout the interface.
The palette should remain controlled and consistent.

Typography
Typography should feel professional and technical.
Use a clean modern sans-serif for:
- Navigation
- Body text
- Tables
- Forms
- Dashboard data
- Buttons
- Labels
Recommended fonts:
- Inter
- Geist
- IBM Plex Sans
- Manrope
Headings can use a slightly stronger display treatment, but they should remain highly readable.
Avoid decorative fonts.
The interface should prioritize readability of engineering and operational information over stylistic typography.
Navigation
Keep the existing NWIS navigation structure.
Only redesign its appearance.
The navigation should feel like an enterprise engineering application.
Use:
- Deep navy background
- Clear white/light text
- Blue active state
- Cream highlight for important selected elements
- Clean icons
- Generous spacing
- Minimal borders
Avoid excessive gradients and glowing effects.
Dashboard Design
The existing dashboard structure must remain unchanged.
Visually, dashboards should use:
- Dark navy backgrounds
- Layered navy cards
- Clear information hierarchy
- Large but restrained statistics
- Minimal charts
- Strong alignment
- Consistent spacing
- Cream highlights for important values
Cards should feel like professional operational instruments, not decorative UI blocks.
Maps and Well Intelligence
NWIS deals heavily with nearby wells and geospatial intelligence.
Map interfaces should therefore be treated as an important product surface.
The redesign should visually support:
- Nearby wells
- Well locations
- Selected wells
- Well relationships
- Geological information
- Drilling information
- Risk indicators
The map itself should remain functional.
Only its visual treatment should change.
Use the NWIS palette around the map interface while maintaining sufficient contrast for geographic information.
AI Interface
NWIS includes AI-assisted intelligence and recommendations.
The AI interface should not look like a generic ChatGPT clone.
It should feel like an engineering intelligence system.

Alerts and Risk Information
Because NWIS is related to drilling intelligence, risk information needs strong visual hierarchy.
Use the existing information categories and functionality.
Do not invent new risk categories.
Visually distinguish:
- Information
- Recommendation
- Warning
- Critical information
without turning the interface into a rainbow of colors.
Use the primary NWIS palette wherever possible and reserve additional semantic colors only where necessary for usability and safety.

Most Important Rule
Do not redesign the product architecture. Redesign the product's visual language.

When modifying the existing application, always ask:
"Can I make this existing component look better without changing what it does?"
If yes, redesign the component visually.
If the answer requires changing the page, route, workflow, data structure, or functionality, do not make that change.
The final result should look like the same NWIS application rebuilt with a consistent premium visual system, not like a completely different application.
